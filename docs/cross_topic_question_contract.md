# 교차 Topic 문항 계약과 증거 판정

열전대·RTD처럼 한 문항이 둘 이상의 Topic Pack을 함께 요구할 때, 각 Pack에 상대 Topic의 문제문을 복제하지 않는다. 각 Pack은 단독 지식의 정본으로 유지하고, `grading/question_contracts/*.json`에서 **문항별 요구 축과 참조 Fact Anchor**를 연결한다.

현재 첫 계약은 열전대·RTD의 `측정원리`, `특성 비교`, `정확도 영향 요인`, `개선 방안` 네 축이다. 계약은 질문에서만 선택된다. 답안 내용으로 Topic을 선택하지 않으며, 검증된 Pack Anchor만 참조한다. 계약의 정규식은 짧은 명시적 관계를 확인하는 수단이지 답안 전체 문장 일치 조건이 아니다.

판정 순서:

1. 질문이 계약의 모든 범위 조건에 해당하고 두 Topic으로 연결되었는지 확인한다.
2. 명시적 오류 관계를 `WRONG`으로 먼저 고정한다. 올바른 원리·조건·인과관계가 확인되면 `SATISFIED`, 개념만 언급되면 `PARTIAL`, 근거가 없으면 `MISSING`으로 판정한다.
3. `PARTIAL`처럼 관계 해석이 필요한 항목만 1회 LLM에 보낸다. LLM에는 해당 Anchor의 검증된 문장과 문제문, 관련 답안 구절(요구당 최대 4줄)만 주며 전체 답안·점수·합격·치명 오류 판정권은 주지 않는다.
4. LLM의 제안은 답안 원문과 완전히 일치하고 해당 요구의 개념어를 포함하는 인용이 있을 때만 **검토 후보로 보관**한다. `PARTIAL`을 `SATISFIED`로 승격하거나 `WRONG`·`SATISFIED`를 바꾸지 않는다. 응답 실패·형식 오류·근거 없는 제안도 기존 결정론 판정을 유지한다.
5. A/B/C/D/E 점수, 상한과 최종 판정은 기존 결정론적 점수 엔진이 계산한다. LLM 호출 여부·검토 후보 건수·요청 해시·오류 유형은 세션 감사 정보로 남긴다. 답안이나 프롬프트 전체를 공개 저장소의 테스트 자료로 넣지 않는다.

이 계약은 첫 비교 문항에 한정한다. 다른 비교 문제로 확장할 때는 질문 범위의 오탐·누락, 정답·부분답·오답 표현, 인용 불일치, 제공자 장애, 점수 변동을 모두 회귀 테스트로 추가한다. LLM의 인용 검증은 근거 위조를 줄이는 장치일 뿐 전문가 판단을 완전히 대체하지 않는다.

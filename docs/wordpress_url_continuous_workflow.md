# WordPress URL → Topic Pack 지속 운영 정책

> **사람용:** WordPress 주소가 들어오면 **원문 수집 → 기존 Topic 대조 → 연결 검토 → 학습 자료 연결 → 필요한 Fact만 별도 검증** 순서로 처리합니다.
> 같은 주소를 다시 받으면 전체를 다시 만들지 않고 **원문 변경 여부와 미완료 단계**부터 확인합니다.
>
> **AI·개발자:** [실행 계약·코드 지도](wordpress_url_continuous_ai_runbook.md) · [WordPress 연결 판정](wordpress_topic_pack_linking_policy.md) · [Fact 적격성](fact_anchor_eligibility_policy.md)

## 1. 장기 목표

블로그에 이미 작성·검토한 지식을 Topic Pack과 연결하여 **찾기 쉬운 학습 자료**로 만들고, 별도 검증을 통과한 사실만 **신뢰할 수 있는 채점 기준**에 반영합니다.

**우선순위는 기존 자산의 정확성·연결·재사용입니다.** URL이 새로 들어왔다고 신규 Topic Pack·새 채점 규칙·새 프로그램을 만들지 않습니다.

## 2. 주소 1건의 표준 작업

| 단계 | 실제 작업 | 완료 시 확인할 것 |
| --- | --- | --- |
| ① 출처 확인 | URL, 게시글 ID, 버전·수정 여부 확인 | 동일 글인지, 신규/변경/변경 없음인지 |
| ② 비공개 수집 | WordPress 본문과 **자사** PDF·이미지 추출/OCR | 수집 상태, 실패 내역, 출처 해시·페이지 |
| ③ 기존 Topic 검색 | 제목뿐 아니라 실제 원문·OCR과 Topic 소유 범위 대조 | 후보 Topic, 기여 내용과 근거 위치 |
| ④ 연결 검토 | 후보별 승인·보류·거절 판단 | 승인된 연결 또는 보류 이유와 다음 조치 |
| ⑤ 학습 연결 | 별도 Master 출처 참조 승인과 비공개 source bundle 생성 | 해당 Topic의 `/review`에서 참조 가능 여부 |
| ⑥ Fact 검토 | 기존 Fact와 중복·누락·충돌·적용조건 비교 | 그대로 유지 / 수정 제안 / 신규 Fact 제안 / 보류 |
| ⑦ 승인·검증 | 내용 변경이 필요한 경우에만 별도 승인·회귀 검증 | 실제 적용 여부와 변경 전후 근거 |

**④ 연결 승인 ≠ ⑤ Master 출처 승인 ≠ ⑥ 기술적 사실 승인 ≠ ⑦ 채점 변경 승인**입니다. 앞 단계의 승인으로 뒤 단계를 건너뛰지 않습니다.

## 3. Topic Pack 판단 원칙

- **이미 충분한 내용**: Fact를 복제하지 않고 출처 또는 학습 예시로 연결합니다.
- **설명이 부족한 내용**: 기존 Topic의 해당 범위만 보완 후보로 만듭니다.
- **잘못된 기존 주장**: 출처·공식 기준·물리법칙으로 반증 가능한 경우 수정·삭제 후보로 만듭니다.
- **새롭고 독립된 문제 단위**: 기존 Topic이 소유할 수 없는 경우에만 신규 Topic 필요성을 검토합니다.
- **증거가 부족한 내용**: `pending_review` 또는 사실 검토 보류로 남겨 두고 점수에 사용하지 않습니다.

한 WordPress 글이 여러 Topic에 **부분 기여**할 수 있으며, 각 연결마다 근거가 필요합니다. 태그·검색 점수·AI 권고만으로 승인하지 않습니다.

## 4. 지켜야 할 경계

- WordPress 원문은 **원본 그대로 보존**합니다. 사용자가 이미지/PDF 텍스트 변환을 요청한 경우에도 본문을 임의로 재작성하지 않습니다.
- 자사 PDF·이미지에 한해 추출/OCR합니다. 외부 PDF·이미지는 메타데이터만 유지합니다.
- 원문·OCR·SQLite DB·개인 답안·세션·인증정보는 공개 GitHub에 올리지 않습니다.
- 학습용 source bundle은 `data/wordpress_topic_packs/`에 비공개로 유지하고, **채점용** `rubrics/topic_packs/`와 구분합니다.
- WordPress 출처를 Master에 연결해도 채점의 A/B/C/D/E, Fact Anchor, fatal 판정은 바뀌지 않습니다.
- AI 기술 검토 위임은 실제 검토자·근거·승인 기록을 요구합니다. 불확실한 내용을 승인하지 않습니다.
- 기존 데이터 변경 전에 백업하고, **검증용 코드 실행을 운영 봇 배포로 오인하지 않습니다.**

## 5. 반복할 때의 우선순위와 방향 이탈 방지

1. **기존 DB·Topic의 무결성 확보**: 백업, 현재 커밋, 승인 상태, 원문 식별정보 확인
2. **미연결·미완료 글 처리**: 기존 Topic 검색과 실질 기여 근거 확보
3. **학습 자료의 연결과 최신화**: 승인된 출처만 Master/Training에 연결
4. **필요한 Fact만 정제**: 중복 제거, 적용 범위 명확화, 오류 수정
5. **자동화는 마지막**: 반복 수작업과 오류가 확인된 단계만 보완

작업 도중 새로운 UI, 챗봇 기능, 채점 공식, 대량 Topic 재구성이 필요해 보이더라도 **현재 URL 처리를 완료하는 데 필수인지** 먼저 판단합니다. 필수가 아니면 별도 개선 후보로만 기록합니다.

## 6. 매번 보고할 결과

| 항목 | 보고 형식 |
| --- | --- |
| 대상 | WordPress URL, 게시글 ID, 신규/변경/동일 여부 |
| 수집 | HTML/PDF/이미지 추출 결과, OCR 실패·보류 |
| Topic | 승인 연결, 보류 후보, 그 근거와 출처 위치 |
| 학습 | 비공개 bundle 및 Master 참조 적용 여부 |
| Fact | 유지/보완/수정/신규/보류 건수와 승인 상태 |
| 검증 | 실행한 실제 검사, 실패·미실행, 백업·변경 파일 |
| 후속 | **남은 작업 1순위**와 차단 이유 |

**끝난 단계만 완료로 기록합니다.** 단순 URL 입력은 수집 완료가 아니고, Git 문서 커밋은 비공개 DB 갱신·실서버 배포가 아닙니다.

## 7. 현재 구현과 목표의 차이

**단일 게시글 URL 통합 실행기** `scripts/wordpress_url_workflow.py`를 구현했습니다. 주소 하나로 해당 글의 수집·변경 감지·비공개 백업·자사 자료 OCR·기존 Topic 후보 검색·개별 보고서 작성까지 처리합니다. 이미 승인된 연결과 Master 출처가 모두 유효하면 Topic 전체의 비공개 학습 bundle도 다시 만듭니다.

```bash
python3 scripts/wordpress_url_workflow.py "https://now0930.pe.kr/wordpress/자기회로/"
```

**자동화되지 않은 승인 단계:** 검색 후보의 의미 판단, Topic link 최종 승인, Master 출처 별도 승인, 독립적인 Fact 검증·채점 변경입니다. 승인에는 reviewer·원문 근거가 필요하고 현재 프로그램은 이를 자동으로 추측하지 않습니다. `--offline`으로 기존 기록을 확인하거나 근거를 갖춘 별도 링크 결정을 적용할 수 있습니다.

현재 CLI는 `/wordpress/<slug>/` 형식의 자사 HTTPS 게시글 URL과 설정된 기술사 카테고리만 수집합니다. 실제 비공개 서버 실행·배포를 마쳤다는 의미는 아닙니다. 명령·선행 조건·회귀 테스트는 [AI 실행 계약](wordpress_url_continuous_ai_runbook.md)을 따릅니다.

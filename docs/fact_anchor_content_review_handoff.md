# Fact Anchor content-review handoff

> **사람용 핵심:** Fact 검토 결과는 근거 검증을 위한 인계 자료입니다. schema 통과와 기술적 진실 검증은 다른 절차입니다.
>
> **AI·개발자:** [코드·권한 참조](ai_implementation_reference.md) · [저장소 정책](../AGENTS.md). 날짜가 붙은 감사 결과는 당시 기록으로 유지합니다.


## Responsibility boundary

| Owner | Responsibility | Cannot do alone |
|---|---|---|
| Codex | Exact-ID alignment, schema, overlay disjointness, fail-closed scoring, source/generated identity and test execution | Declare a technical statement true from format checks |
| ChatGPT content reviewer | Compare each of the 80 held original statements with first-party technical sources; record conditions, counterexamples and a proposed correction | Remove scoring holds, edit generated banks or claim release success |
| Managed Topic Pack workflow | Apply only evidence-backed corrections, source-hash approval, generated rebuild and regression validation | Bypass release/approval gates |

The immutable starting packet is
[`reports/fact_anchor_revision_chatgpt_review_80_20261102.csv`](../reports/fact_anchor_revision_chatgpt_review_80_20261102.csv).
It has 80 rows and is regenerated by
`python3 scripts/export_fact_anchor_revision_review.py --write`; check drift with
the same command without `--write`. **Make a separate copy for completed review
answers**; do not fill the generated starting packet in place.

For each row, the reviewer must identify an authoritative original document,
the exact section/page/formula, the part of the claim it supports and its
application conditions. Use `KEEP_WITH_CORRECTION` only when the corrected
proposition is directly supported; otherwise record `HOLD_INSUFFICIENT_EVIDENCE`
or `EXCLUDE_FROM_GENERAL_SCORING`. Neither a legacy Registry `verified` label
nor an existing URL alone counts as a review. The `existing_primary_source_urls`
column is a lead to inspect, not approval evidence. Preserve source history
and do not include private answers or operating databases in the review copy.

After content review, Codex validates the returned CSV's 80 exact IDs,
nonempty source URLs, locators and conditions for proposed corrections with
`python3 scripts/validate_fact_anchor_content_review.py <completed-copy.csv>`.
This checks format only, not whether a source actually proves a claim. Then Codex changes
one canonical Topic Pack at a time through the managed workflow. Registry and
generated projections follow that source; only then can a corresponding hold
be considered for removal. The remaining holds and all unrelated grading
contracts stay fixed. Full Release Gate must pass before commit/push/deploy.

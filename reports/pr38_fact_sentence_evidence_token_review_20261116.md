# Fact sentence simplification: evidence-token impact

The scoring policy and grading implementation were not changed. This review checks the consequences of changing source text consumed by the existing deterministic evidence adapter; it does not certify overall routing or score equivalence.

`grading/evidence/fact_anchor_evidence_adapter.py::_anchor_tokens` combines the Anchor `statement` and first `accepted_explanations` entry. `evaluate_fact_anchor_requirements` computes token coverage using that set and uses thresholds for `SATISFIED` and `PARTIAL`. Earlier simplification batches inserted a rewritten sentence as the first accepted explanation and changed the token set. These changes were on the PR branch only; no production deployment is asserted.

Against baseline `e375055f19e5953312b92fb188c658aebfa1ea9a`, a synthetic answer `온도에서 온도에 포화수증기압은 분압 rh` to the relative-humidity Anchor was evaluated with the actual adapter and an isolated copy of each source: baseline `SATISFIED` / coverage `0.333333`, rewritten source `PARTIAL` / `0.269231`. The synthetic text is deliberately sparse and is not a real learner answer; no whole-answer score or user impact is asserted. Nine other synthetic answers for relative humidity, dew point, quadrature and thermocouple junction dependence had unchanged statuses while several coverage values changed. A passing full pytest on those earlier trees did not establish semantic equivalence.

Corrective steps: restore the exact original accepted-explanation lists and their order; restore the capacitive and resistive humidity and two thermocouple Anchors to baseline pending a narrower safe proposal; and use separately source-reviewed short original-wording alternatives. Their former `previous_statement` values and independent `gpt-6-luna` review appear in `pr38_humidity_token_neutral_review_20261116.md` and `pr38_rotation_token_neutral_review_20261116.md`.

The factual statement also feeds generated Topic-routing triggers. In the fallback fact-bank route, the synthetic question `Subzero moisture specification에서 frost point 계산 기준을 설명하시오.` routed to the humidity Topic at `e375055`, but to a valve-positioner Topic after the frost-point sentence was shortened. The frost-point source and generated reference were therefore restored to baseline and the proposed shortening remains pending. A regression now checks that this question retains the humidity Topic; another checks the missing-tooth encoder question. The latter question's selected Topic was stable before restoration, but its routing score differed. These synthetic checks do not establish general routing equivalence.

In a further direct check of `_build_canonical_axis_context` in `grading/evidence/logic_check_evaluator.py`, each of the six shortened source Anchors produced three isolated canonical axes instead of the baseline two: the shortened statement and its unchanged full accepted explanation became separate axes. These axes are used in D/E evidence validation; this demonstrates a duplicate-axis risk but does not itself prove an actual D/E score change. No grading policy or code was changed to suppress this. All six source Anchors were restored to their baseline wording and the shorter source-reviewed alternatives remain non-scoring proposals in the two review reports. Thus all 48 original simplification candidates remain unapplied; the previously reviewed encoder frequency correction is separate.

The token-neutral comparison and temporary explanation-hash checks did not prove unchanged reference-span ranking, Topic routing, other grading paths, or identical total scores. The `expected` compatibility-field idea was tested only in an isolated scratch copy: it preserved generated triggers but did not preserve statement-only question scope and introduced an ambiguous long grading field, so it was not adopted. Existing pending-candidate protection remains in place. The synthetic fallback-routing regression tests document that the restored frost-point and missing-tooth examples keep their previously observed Topic owners. Any future canonical shortening needs an explicitly reviewed compatibility design and focused tests for lexical evidence, axis ownership, question scope and routing before promotion.
